# Рецепты интеграций

Пошаговые рецепты, как подключить Enitor к другим инструментам. Всё здесь
работает на твоём устройстве, без нашего сервера — его нет. Исключение —
раздел 8: там используется сервер, который ты запускаешь сам. Точные форматы
запросов — в [formats.ru.md](formats.ru.md).

Экран интеграций открывается через **Настройки → Интеграции**. Названия ниже —
те, что ты видишь на экране.

## Что работает на этом устройстве

- **Tasker и Automate** (Android): добавлять задачи, читать план на день.
- **ИИ-ассистенты** (Windows, Claude Desktop и похожие): ассистент через MCP
  запускает `enitor-cli` на твоём компьютере.
- **enitor-cli** (Windows): добавлять и закрывать задачи из консоли или из
  задания по расписанию.
- **Вебхуки**: Enitor отправляет события на адреса, которые ввёл *ты* — n8n,
  Home Assistant, скрипт на твоей машине.
- **Файлы календарей**: импорт `.ics` или ссылки на календарь, экспорт
  расписания в `.ics`; переезд из Todoist, Google Задач или TickTick.

Ничего не уходит с устройства, пока ты это не включишь. Права выключены по
умолчанию, а каждый адрес вебхука — отдельное решение. Свой сервер (раздел 8) —
ещё одна вещь, которую ты включаешь сам.

## 1. Tasker (Android)

### Получить ключ

1. **Настройки → Интеграции → Tasker и Automate**.
2. В блоке **Ключ** нажми **Показать** и скопируй ключ.
3. Храни его при себе. Любой, у кого есть ключ, может отправлять команды,
   пока ключ действует. **Новый ключ** выпускает другой, и старый сразу
   перестаёт работать.

### Разреши

**Настройки → Интеграции → Права → Tasker и Automate**:

- **Добавлять задачи и пункты расписания, отмечать выполненное — без
  вопросов**: включи, чтобы Tasker мог добавлять задачи.
- **Читать план на день**: включай, только если хочешь, чтобы Tasker читал
  твой план. Приложение попросит подтвердить.

Команды без верного ключа игнорируются, а пока переключатель Tasker выключен,
все команды получают отказ.

### Добавить задачу

Создай задачу Tasker с одним действием **Send Intent**:

| Поле | Значение |
|---|---|
| Action | `dev.enitor.app.COMMAND` |
| Package | `dev.enitor.app` |
| Target | Broadcast Receiver |
| Extra | `key:` и дальше твой ключ |
| Extra | `command:{"command":"add_task","args":{"title":"%par1"}}` |

`%par1` — первый аргумент, с которым запущена задача. Туда можно поставить
любую переменную Tasker, например `%TITLE`, главное — оставить её внутри
кавычек.

Тот же пример есть на экране Tasker под кнопкой **Скопировать пример**.

### Прочитать план на день с ответом

Для этого нужно право **Читать план на день** в Правах.

1. Создай задачу Tasker с действием **Send Intent**:

   | Поле | Значение |
   |---|---|
   | Action | `dev.enitor.app.COMMAND` |
   | Package | `dev.enitor.app` |
   | Target | Broadcast Receiver |
   | Extra | `key:` и дальше твой ключ |
   | Extra | `command:{"command":"list_today"}` |
   | Extra | `reply_package:net.dinglisch.android.taskerm` |

2. Создай в Tasker **профиль**: **Event → Intent → Intent Received** с
   Action `dev.enitor.app.REPLY`. Привяжи его к задаче, которая читает
   переменную **%reply**. Ответ — JSON-строка с полями `result.tasks` и
   `result.schedule`. Разобрать её можно действием JavaScriptlet, а пока
   формат не ясен — просто покажи `%reply` в уведомлении.

Ответ уходит только тому пакету, который указан в `reply_package`, и только
если он есть в списке **Кому можно отвечать** у Tasker и Automate. Tasker
в этом списке по умолчанию.

Automate работает так же, с пакетом `com.llamalab.automate`.

Каждая команда оставляет тихую отметку в шторке. Чтобы её убрать, выключи
**Уведомлять о каждой команде**.

## 2. Claude Desktop на Windows (MCP)

Ассистент сам запускает `enitor-cli` и видит только то, что разрешено в
Правах.

### Скопируй настройку

1. **Настройки → Интеграции → ИИ-ассистенты**.
2. В блоке **Настройка для Claude Desktop (claude_desktop_config.json)**
   нажми **Скопировать настройку**.

Это небольшой JSON. Строка `command` — полный путь к `enitor-cli.exe`, который
лежит рядом с `enitor.exe`. Если переложишь папку с Enitor, скопируй настройку
заново.

### Вставь в конфиг

1. Нажми **Win + R**, введи `%APPDATA%\Claude` и нажми Enter.
2. Открой `claude_desktop_config.json` в этой папке. Если файла нет, создай.
3. Если в файле уже есть раздел `"mcpServers"`, вставь туда только запись
   `"enitor"`. Второй ключ `"mcpServers"` не добавляй — файл тогда не
   откроется. Проще всего, если файл пустой: тогда вставляешь весь блок.
4. Сохрани файл.
5. Полностью закрой Claude Desktop (правой кнопкой по значку в трее, выход)
   и открой снова.

### Разреши

**Настройки → Интеграции → Права → ИИ-ассистенты**:

- **Добавлять** — ассистент может добавлять задачи и отмечать их выполненными.
- **Читать план на день** — ассистент может читать твой план.

> **Внимание к чтению.** Когда «Читать» включено, названия задач, время и
> теги уходят в модель ассистента. Она работает на серверах провайдера
> ассистента, а не на твоём устройстве. Сам Enitor никуда ничего не отправляет.
> Держи «Читать» выключенным, пока это тебя не устраивает.

Чтобы посмотреть, что ассистент уже делал, открой блок **Последние вызовы**
на том же экране. Там есть кнопка **Очистить**.

## 3. n8n

n8n — инструмент для сценариев, его можно запустить у себя или пользоваться
облачной версией. Рецепт ниже принимает события Enitor и проверяет их подпись.

### Создай вебхук

1. В n8n добавь узел **Webhook**. **HTTP Method** — `POST`, **Path** — например
   `enitor`.
2. Открой **Options** и включи **Raw Body**. Подпись считается по точным
   байтам, которые отправил Enitor, поэтому n8n не должен их пересобирать.
3. Скопируй **Production URL** узла.

### Добавь адрес в Enitor

1. **Настройки → Интеграции → Вебхуки → Добавить адрес**.
2. Вставь адрес и выбери события (например **Задача выполнена**).
3. Сохрани и скопируй **Секрет подписи** с того же экрана.
4. Нажми **Проверить**, чтобы отправить `ping`. Убедись, что n8n его получил.

### Проверь подпись

После узла Webhook добавь узел **Code** в режиме JavaScript. Вместо заглушки
вставь секрет. Код:

```javascript
const crypto = require('crypto');

const SECRET = 'вставь сюда секрет подписи';
const MAX_AGE_SECONDS = 5 * 60;

const { headers } = $input.first().json;

// С включённым Raw Body узел Webhook кладёт точные байты тела в двоичное
// свойство data. Подпись считается именно по ним, а не по разобранному JSON.
const buffer = await this.helpers.getBinaryDataBuffer(0, 'data');
const rawBody = buffer.toString('utf8');

const timestamp = headers['x-enitor-timestamp'];
const signature = headers['x-enitor-signature'] || '';

const age = Math.abs(Date.now() / 1000 - Number(timestamp));
const fresh = Boolean(timestamp) && Number.isFinite(age) && age <= MAX_AGE_SECONDS;

const expected =
  'sha256=' +
  crypto.createHmac('sha256', SECRET).update(`${timestamp}.${rawBody}`).digest('hex');

const a = Buffer.from(signature);
const b = Buffer.from(expected);
const sameLength = a.length === b.length;
const signatureOk = sameLength && crypto.timingSafeEqual(a, b);

if (!fresh || !signatureOk) {
  return [{ json: { ok: false } }];
}

return [{ json: { ok: true, event: JSON.parse(rawBody) } }];
```

Затем добавь узел **IF** с условием `{{ $json.ok }}`. Ветка «true» — твой
дальнейший сценарий. Ветка «false» — узел **Respond to Webhook** с кодом
`401`. Это важно: Enitor повторяет любой ответ, кроме `2xx`, поэтому на
подделку лучше ответить внятным отказом, а не `500`.

Два момента:

- Не пересобирай тело через `JSON.stringify` перед проверкой. Байты должны
  совпадать с тем, что подписано.
- Если доставка не получила `2xx`, Enitor повторит её через 1 мин, 5 мин,
  30 мин, 2 ч и 12 ч. Сценарий должен отвечать быстро.

По умолчанию n8n не даёт Code-узлу подключать модули, и
`require('crypto')` выдаст ошибку. Разреши только его переменной окружения
`NODE_FUNCTION_ALLOW_BUILTIN=crypto` (если n8n работает с Task Runners —
у раннера, а не у основного процесса) и перезапусти n8n. Если менять
окружение нельзя, вычисли HMAC узлом **Crypto** по двоичному свойству `data`
и сравни в узле IF; такое сравнение не выполняется за постоянное время,
поэтому адрес Enitor держи в секрете.

## 4. Home Assistant

Home Assistant умеет принять вебхук и запустить по нему автоматизацию. Подпись
Enitor он **не проверяет**. Защита — в том, что адрес остаётся в домашней сети.

### Создай автоматизацию

1. **Настройки → Автоматизации и сцены → Создать автоматизацию → Создать новую
   автоматизацию → Редактировать в YAML**.
2. Вставь текст ниже и замени идентификатор вебхука и службу уведомлений:

```yaml
alias: Enitor — день закрыт
description: Сообщить, когда все задачи дня выполнены
triggers:
  - trigger: webhook
    webhook_id: enitor-day-closed-9f3a1c7d
    local_only: true
    allowed_methods:
      - POST
actions:
  - action: notify.mobile_app_your_phone
    data:
      title: День закрыт
      message: >-
        Выполнено {{ trigger.json.data.done }} из {{ trigger.json.data.total }} задач,
        продуктивность {{ trigger.json.data.productivity }}%
mode: single
```

Придумай свой длинный случайный `webhook_id`. Вместо
`notify.mobile_app_your_phone` укажи службу уведомлений своего телефона.
Сохрани.

### Укажи адрес в Enitor

**Настройки → Интеграции → Вебхуки → Добавить адрес**:

- Адрес: `http://homeassistant.local:8123/api/webhook/enitor-day-closed-9f3a1c7d`
  (свой адрес Home Assistant и тот же `webhook_id`).
- Событие: **День закрыт**.

Enitor предупредит, что адрес начинается с `http://`. Для Home Assistant в
домашней сети это нормально, и именно поэтому адрес должен оставаться дома.

### Как это защитить

- `local_only: true` заставляет Home Assistant отказывать в запросах не из
  локальной сети, в том числе в запросах через облачный удалённый доступ.
- `webhook_id` — единственный секрет в этой схеме. Обращайся с адресом, как с
  паролем: не публикуй его и не клади на скриншоты.

## 5. Свой сервер (любой язык)

Это общий случай: Enitor отправляет `POST` на адрес, который ты держишь сам,
а твой код проверяет подпись. В каждом запросе есть заголовки:

- `X-Enitor-Event` — тип события, например `task.completed`.
- `X-Enitor-Timestamp` — время в секундах Unix.
- `X-Enitor-Signature` — `sha256=` и hex от HMAC-SHA256 строки
  `timestamp + "." + body` с секретом подписи как ключом.

Чтобы проверить запрос: пересчитай HMAC по точным байтам тела, сравни
функцией с постоянным временем и отбрасывай метки времени старше пяти минут.
Для одного и того же факта Enitor присылает один и тот же `id`, так что, если
повтор может что-то сломать, запоминай уже обработанные `id`.

Минимальный приёмник на Python:

```python
import hashlib
import hmac
import json
import time
from http.server import BaseHTTPRequestHandler, HTTPServer

SECRET = b"вставь сюда секрет подписи"
MAX_AGE_SECONDS = 300


def signature_ok(headers, body: bytes) -> bool:
    timestamp = headers.get("X-Enitor-Timestamp", "")
    signature = headers.get("X-Enitor-Signature", "")
    if not timestamp.isdigit() or abs(time.time() - int(timestamp)) > MAX_AGE_SECONDS:
        return False
    expected = "sha256=" + hmac.new(
        SECRET, timestamp.encode() + b"." + body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature, expected)


class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        length = int(self.headers.get("Content-Length", 0))
        body = self.rfile.read(length)
        if not signature_ok(self.headers, body):
            self.send_response(401)
            self.end_headers()
            return
        event = json.loads(body)
        print(event["type"], event["id"])
        self.send_response(200)
        self.end_headers()


HTTPServer(("127.0.0.1", 8787), Handler).serve_forever()
```

Запусти его и добавь `http://127.0.0.1:8787` в **Вебхуки**. Enitor покажет
предупреждение про `http://`. Сервер на том же компьютере, доступный по
`127.0.0.1`, никуда с машины не выходит.

## 6. enitor-cli на Windows

`enitor-cli` говорит с запущенным Enitor через канал, который может открыть
только твой пользователь Windows. Это отдельная программа, она идёт в сборке
для Windows.

### Найди путь

**Настройки → Интеграции → Windows → Консоль: enitor-cli → Скопировать путь.**
Это полный путь к `enitor-cli.exe`.

### Вызов из консоли

```text
enitor-cli add Купить молоко --date 2026-11-02 --at 18:00 --tag home
enitor-cli today --json
enitor-cli done 3f9a
```

Коды выхода: `0` — успех, `2` — неверные аргументы, `3` — Enitor не запущен,
`4` — запрещено (посмотри Права), `5` — любой другой отказ.

Чтобы вызывать `enitor-cli` из любой папки, добавь папку с `enitor-cli.exe`
в PATH сам. Enitor системные настройки не меняет.

### Запуск из Планировщика заданий

Так можно добавлять задачу каждое утро.

1. Открой **Планировщик заданий** → **Создать простую задачу**.
2. **Триггер**: ежедневно, в 08:00.
3. **Действие**: запуск программы.
4. **Программа или сценарий**: полный путь, который ты скопировал, в кавычках,
   если в нём есть пробелы.
5. **Добавить аргументы**: `add "Проверить почту" --tag work`
6. В **Свойствах** задачи выбери **Выполнять только для пользователя, вошедшего
   в систему**. Канал открыт только твоему пользователю, поэтому задача должна
   идти от твоего имени.

Если Enitor закрыт, `enitor-cli` запустит его свёрнутым и подождёт до 10
секунд. Каждый запуск добавляет новую задачу, поэтому ставь расписание раз в
день, а не каждую минуту.

## 7. Календари и переезд

### Импорт расписания (.ics)

Подходит для расписания пар в вузе или графика смен.

1. **Настройки → Интеграции → Календари и переезд → Импорт календаря из файла
   (.ics)**.
2. Выбери файл. Enitor сначала покажет предпросмотр, включая пункты, которые
   импортировать не может (события на весь день, «второй вторник», годовые
   правила), и причину.
3. Импортируй. Пункты появятся во вкладке **Расписание**.

Повторный импорт того же календаря обновляет пункты, а не дублирует их.

### Импорт по ссылке

1. **Импорт календаря по ссылке**: вставь ссылку на `.ics` и нажми
   **Загрузить**.
2. Календарь загружается один раз, по нажатию кнопки. **Обновлять раз в день
   при открытии** по умолчанию выключено. Если включить, сервер календаря
   видит каждый запрос: твой адрес и время.

Ссылка на `http://` получит предупреждение. Загружай такую, только если доверяешь
сети.

### Экспорт в календарь

**Экспорт в календарь (.ics)** сохраняет расписание и задачи со временем за
последние 30 дней. Файл открывают Google Календарь, Outlook и Apple Календарь.

### Переезд из другого приложения

**Настройки → Интеграции → Переезд из другого приложения**. Сначала экспортируй
файл из старого приложения, потом выбери его здесь. Перед импортом ты увидишь
предпросмотр.

- **Todoist**: в проекте **⋯ → «Экспортировать как шаблон» (CSV)**.
- **Google Задачи**: на takeout.google.com выбери **Задачи**, затем файл
  **Tasks.json**.
- **TickTick**: **Настройки → Аккаунт → «Создать резервную копию» (CSV)**.

## 8. Синхронизация телефона и ПК через свой сервер

Enitor может синхронизироваться через сервер, который ты запускаешь сам: на
компьютере или домашнем сервере. Это не раздел 5, там про приём вебхуков.
Полное описание, со всеми маршрутами и правилами, — в [server.ru.md](server.ru.md).

### Запусти сервер

Запусти `enitor-server` с папкой для данных:

```
enitor_server.exe --data C:\enitor-data
```

При первом запуске сервер печатает токен. Чтобы увидеть его снова, запусти ту
же программу с опцией `--show-token`.

### Подключи телефон и ПК

На каждом устройстве открой **Настройки → Синхронизация → Свой сервер**, нажми
**Подключить сервер** и введи адрес и токен. В первый раз выбери
**Объединить с данными на сервере**.

Дома запусти сервер с `--host 0.0.0.0` и используй адрес компьютера, например
`http://192.168.1.10:8787`. Снаружи дома нужен адрес с HTTPS; как его поставить
через Caddy, описано в инструкции.

### Используй из автоматики

Автоматика передаёт тот же токен в заголовке `Authorization`. Вот как добавить
задачу на сегодня. `BASE` — адрес сервера, например `http://127.0.0.1:8787`,
если скрипт работает на том же компьютере:

```bash
curl -s -X POST "$BASE/v1/tasks" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk"}'
```

Маршруты и другие примеры — в [server.ru.md](server.ru.md).

## Облачные сервисы

Облачные сервисы вроде n8n Cloud или Make тоже умеют принимать вебхуки. Их
адрес вводишь в **Вебхуки** так же, как свой. Тогда события проходят через их
серверы, и относиться к этому стоит так же осторожно, как к любой сторонней
службе. Свой сервер (раздел 8) облачным сервисом не является: он работает на
твоей машине.

## Чего здесь пока нет

У Enitor нет своего сервера, и ни один рецепт выше его не требует. REST-доступ и
ленту изменений, о которых спрашивают, даёт твой собственный сервер, см. раздел 8.
Некоторых других вещей пока нет:

- подписки на календарь, которую отдаёт Enitor,
- Telegram-бота,
- писем.

Всё это — позже, и только со своим сервером, который запускаешь у себя.
Наш сервер для этого не появится.
