# Форматы интеграций Enitor

Версия формата **1**. Каждый пример в этом файле проверяется тестом: его
разбирает тот же код, что и приложение, так что пример, который перестал
работать, ломает сборку.

Enitor хранит всё на твоём устройстве. Ничто здесь не обращается к нашему
серверу — его нет. Каждый формат ниже — это способ, которым *твои* инструменты
на *твоём* устройстве говорят с Enitor, или способ, которым Enitor обращается к
адресу, который ввёл *ты*.

## Версии

- Каждый формат несёт версию: `v=1` в ссылках, `"v": 1` в JSON.
- Enitor понимает **текущую и предыдущую** версию каждого формата.
- Поля, которых приложение не знает, **никогда не отбрасываются молча**: ссылки
  показывают их в форме подтверждения, ответы JSON перечисляют их в `warnings`.
- Отсутствующая версия означает `1`.
- Версия новее той, которую понимает приложение, отклоняется с ошибкой
  `unsupported_version` — приложение никогда ничего не угадывает.

## 1. Ссылки: `enitor://`

Открываются из браузера, заметки, QR-кода, лаунчера. Ссылка **сама по себе
ничего не добавляет**: она открывает обычную форму задачи (или расписания)
уже заполненной, с пометкой «из ссылки», и ты нажимаешь «Добавить».

| Действие | Параметры |
|---|---|
| `enitor://add` | `title`, `desc`, `date`, `start`, `end`, `priority`, `tags` |
| `enitor://schedule` | `title`, `date`, `start` (обязательно), `end`, `location`, `note` |
| `enitor://open` | `screen` = `today` \| `schedule` \| `goals` \| `settings` \| `integrations` |

Общий параметр `v` (версия, по умолчанию `1`).

Правила значений:

- Текст в UTF-8, с процентным кодированием (`%20` или `+` для пробела). Декодируется
  **один раз**: `%2520` остаётся буквальным текстом `%20`.
- `title` — до 500 символов после обрезки пробелов. Ссылка без заголовка
  открывает пустую форму (плитка быстрых настроек делает именно это); команды
  (раздел 2) требуют заголовок.
- `desc`, `note` — до 5000 символов; `location` — до 500. Более длинное значение
  отклоняется, а не обрезается.
- `date` — `YYYY-MM-DD`, в пределах 5 лет от сегодня. Если нет — сегодня; до
  04:00 «сегодня» всё ещё вчера, как и везде в Enitor.
- `start`, `end` — `HH:MM` (ведущий ноль можно опустить: `9:05`), от 00:00 до
  23:59. `end` должен быть позже `start`.
- `priority` — `none` \| `low` \| `medium` \| `high`, без учёта регистра.
- `tags` — через запятую, до 10 тегов по до 40 символов, символ `#` удаляется.

Примеры:

```link
enitor://add?title=Buy%20milk
enitor://add?v=1&title=Call%20mom&date=2026-11-02&start=18:00&end=18:30&priority=high&tags=family
enitor://schedule?title=Physics&date=2026-11-03&start=09:00&end=10:30&location=Room%20214
enitor://open?screen=schedule
enitor://add
```

«Поделиться → Enitor» на Android работает так же: первая строка общего текста
становится заголовком, остальное (например, ссылка) — описанием, а форма
открывается с пометкой «из „Поделиться“».

## 2. Команды (Tasker, `enitor-cli`, MCP, виджет)

Одна модель для всех входов с ключом. Запрос:

```json
{
  "v": 1,
  "command": "add_task",
  "idempotencyKey": "tasker-2026-11-02-milk",
  "args": { "title": "Buy milk", "date": "2026-11-02" }
}
```

- `idempotencyKey` (необязательно, до 100 символов): повтор с тем же ключом в
  течение 7 дней возвращает первый ответ и ничего не создаёт. Без ключа каждый
  запрос — новый.
- Правила полей те же, что у ссылок; `title` обязателен.

### Команды

| Команда | `args` | `result` |
|---|---|---|
| `add_task` | `title`, `description`, `date`, `start`, `end`, `priority`, `tags` | `{ "task": Task }` |
| `add_schedule_item` | `title`, `date`, `start` (обязательно), `end`, `location`, `note` | `{ "item": ScheduleItem }` |
| `complete_task` | `id` — полный id или однозначный префикс длиной не меньше 4 символов | `{ "task": Task }` |
| `list_today` | `date` (необязательно) | `{ "date": "YYYY-MM-DD", "tasks": [Task], "schedule": [ScheduleItem] }` |

Ещё примеры:

```json
{ "v": 1, "command": "add_schedule_item", "args": { "title": "Physics", "date": "2026-11-03", "start": "09:00", "end": "10:30", "location": "Room 214" } }
```

```json
{ "v": 1, "command": "complete_task", "args": { "id": "3f9a" } }
```

```json
{ "v": 1, "command": "list_today" }
```

`Task`:
`{ "id", "title", "description"?, "date", "start"?, "end"?, "priority", "tags", "done" }`.
`ScheduleItem`:
`{ "id", "title", "date", "start", "end"?, "location"?, "note"? }` —
`date` — день, в который событие происходит.

Кому что можно, задаётся в Enitor → Настройки → Интеграции → Права:
«Добавлять» (добавлять, отмечать выполненным) и «Читать» (`list_today`) для
каждого входа. Всё выключено, пока ты не включишь; виджет может отмечать задачи
выполненными, но никогда не читает.

### Ответы

```reply
{ "v": 1, "ok": true, "result": { "task": { "id": "0b1c2d3e", "title": "Buy milk", "date": "2026-11-02", "priority": "none", "tags": [], "done": false } }, "warnings": [] }
{ "v": 1, "ok": false, "error": { "code": "forbidden", "message": "This is turned off in Enitor → Settings → Integrations → Permissions." }, "warnings": [] }
```

`message` — человекочитаемый текст на языке приложения; `field` называет поле
для `invalid_args`.

| `code` | Значение |
|---|---|
| `invalid_args` | Поле отсутствует, слишком длинное или вне диапазона |
| `unknown_command` | Такой команды нет |
| `unsupported_version` | `v` новее, чем понимает приложение |
| `forbidden` | Этому входу нельзя это делать (Права) |
| `bad_key` | Tasker: ключ отсутствует или неверный |
| `not_found` | `complete_task`: задачи с таким id нет (или префикс неоднозначен) |
| `internal` | Что-то пошло не так внутри приложения; ничего не изменено |
| `not_ready` | Windows: Enitor ещё запускается — повтори через минуту |

### Транспорты

**Android — Tasker, Automate и подобные.** Явный broadcast (Tasker:
*Send Intent*, Target *Broadcast Receiver*):

- Пакет `dev.enitor.app`, Action `dev.enitor.app.COMMAND`;
- extras: `key` — ключ из Интеграции → Tasker; `command` — JSON-запрос выше
  строкой; по желанию `reply_package` и `request_id`.

Ответы отправляются, только если `reply_package` есть в разрешённом списке в
Интеграциях (по умолчанию Tasker и Automate): broadcast `dev.enitor.app.REPLY`
**только этому пакету**, extras `reply` (JSON-ответ) и `request_id`. Ничего
Ничего не рассылается всем приложениям. Каждая команда оставляет тихое
уведомление (его можно выключить).

**Windows — `enitor-cli` и MCP.** Именованный канал
`\\.\pipe\Enitor-<user SID>`, открытый только текущему пользователю и только
локально. Кадр: 4-байтовая длина в порядке little-endian + UTF-8 JSON, не более
64 КБ; один ответ на один запрос; таймаут 5 с. Кадр — это конверт:

```pipe
{ "v": 1, "kind": "ping" }
{ "v": 1, "kind": "permissions", "source": "mcp" }
{ "v": 1, "kind": "command", "source": "cli", "request": { "v": 1, "command": "list_today" } }
{ "v": 1, "kind": "link", "url": "enitor://add?title=Milk" }
```

`source` — `cli` или `mcp`; всё остальное считается `cli`. На `ping` и
`link` ответ — `{ "ok": true, "result": {} }`; на `permissions` —
`{ "ok": true, "result": { "add": bool, "read": bool } }`: что этому входу
можно (MCP по нему показывает только разрешённые инструменты). `enitor-cli`
говорит на этом языке за тебя:

```text
enitor-cli add Buy milk --date 2026-11-02 --at 18:00 --tag home
enitor-cli today --json
enitor-cli done 3f9a
```

Коды выхода: 0 — успех, 2 — неверные аргументы, 3 — Enitor не запущен,
4 — запрещено, 5 — любой другой отказ.

**MCP (ИИ-ассистенты).** `enitor-cli mcp` — MCP-сервер поверх stdio
(JSON-RPC 2.0, версии протокола 2025-06-18, 2025-03-26, 2024-11-05). Инструменты
— четыре команды выше с входными схемами JSON Schema; `list_today` даже не
показывается, пока не разрешено «Читать». Если Enitor закрыт, `enitor-cli`
запускает его свёрнутым и ждёт до 10 с. Текст задач возвращается как данные
(`structuredContent`), никогда не смешивается с инструкциями.

## 3. События вебхуков

Enitor отправляет `POST` на адреса, которые ты добавил, только для того, что
ты **сделал на этом устройстве**. Отмена действия не отправляет событие
«отмена».

```event
{
  "v": 1,
  "id": "evt_3f9a6c0de1b24a7f9c8d0e1f",
  "type": "task.completed",
  "createdAt": "2026-11-02T18:31:05.120+03:00",
  "data": { "task": { "id": "0b1c2d3e", "title": "Call mom", "date": "2026-11-02", "priority": "high", "tags": ["family"], "done": true } }
}
```

| `type` | `data` |
|---|---|
| `task.completed` | `{ "task": Task }` |
| `day.closed` | `{ "date": "YYYY-MM-DD", "done": int, "total": int, "productivity": 0…100 }` — выполнена каждая задача дня |
| `goal.achieved` | `{ "goal": { "id", "title", "period", "target"?, "progress" } }` |
| `ping` | `{}` — отправляется кнопкой «Проверить» |

`id` — хеш от id записи, типа и версии формата: повтор одного и того же факта
имеет тот же `id`, поэтому получатели могут отбрасывать дубликаты.

Заголовки:

- `Content-Type: application/json`
- `X-Enitor-Event: task.completed`
- `X-Enitor-Delivery: <случайный id этой серии попыток>`
- `X-Enitor-Timestamp: <unix seconds>`
- `X-Enitor-Signature: sha256=<hex HMAC-SHA256(secret, timestamp + "." + body)>`

Чтобы проверить доставку: пересчитай HMAC по точным байтам тела, сравни за
постоянное время и отклоняй метки времени старше 5 минут.

Доставка: `2xx` — доставлено. `410 Gone` — адрес выключен, и ты получаешь
уведомление. Всё остальное, таймаут (10 с) или отсутствие сети — повтор через
1 мин, 5 мин, 30 мин, 2 ч, 12 ч, потом статус «не доставлено». В очереди
ждут не более 500 доставок; журнал хранит 7 или 30 дней.

## 4. Полный экспорт

Настройки → Интеграции → Полный экспорт: один JSON-файл со всеми твоими данными.

```export
{
  "format": "enitor-export",
  "v": 1,
  "exportedAt": "2026-11-02T18:31:05.120",
  "app": { "version": "0.4.0" },
  "data": { "tasks": [], "goals": [], "schedule": [], "recurrence": [], "templates": [], "scheduleTemplates": [], "taskBacklog": [], "goalBacklog": [], "dayRatings": {}, "periodRatings": {} }
}
```

В каждом разделе — записи приложения в том виде, в каком оно их хранит (все
поля перечислены в схемах): даты — полные локальные метки ISO 8601,
`priority` — номер (0 — нет … 3 — высокий). Ключи `dayRatings` — полночь дня
(`2026-11-02T00:00:00.000`), ключи `periodRatings` — `w-<понедельник>` для
недели, `m-YYYY-MM`, `s-YYYY-N` (сезон) и `y-YYYY`; значения — 1…10.

В нём никогда нет состояния, которое существует только на устройстве
(настройки интеграций, очередь и журнал вебхуков, снимок виджета), производных
чисел (дневная статистика — она пересчитывается) и секретов (ключ Tasker и
секреты вебхуков хранятся в защищённом хранилище системы). JSON Schema:
`docs/integrations/schema/`.

## 5. Файлы календаря (.ics)

Импорт: `VEVENT` из RFC 5545 превращаются в пункты расписания. Еженедельные
(в том числе раз в две недели), ежемесячные по дню и ежедневные с шагом N
правила переносятся напрямую; `UNTIL`/`COUNT` задают конец, `EXDATE` — пропущенные
дни. Того, что Enitor не может выразить (события на весь день, «второй вторник»,
ежегодные), не импортируется, и причина показывается до импорта. Повторный
импорт того же календаря обновляет пункты, а не дублирует их (id пункта
выводится из `UID` события). Ссылка на календарь загружается один раз, по
нажатию кнопки; ежедневное обновление — отдельный переключатель, по умолчанию
выключен.

Экспорт: расписание, повторяющиеся задачи со временем и задачи со временем за
последние 30 дней и позже, с `RRULE`/`EXDATE`, текущим часовым поясом
как `TZID` + `VTIMEZONE`, концами строк CRLF, строками, переносимыми на 75
октетах, и стабильными `UID`.
